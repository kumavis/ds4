# D19 — End-of-sweep cache refill and S3-FIFO eviction

On the int4 branch, refilling only cold layers raised decode speed 2.9% in a 31k plain session and 4.1% across seven matched DSpark turns. The nine plain replies matched on all 2,316 generated token IDs. The seven matched DSpark turns had identical visible reply text, lengths and rounds/accepted counts. Their raw D8 logs recorded 326 of the 1,743 generated token IDs, and those 326 matched. Full DSpark token-ID equality remains unverified. S3-FIFO passed the single-prompt and sequence gates. Its session speed remains unmeasured.

## Implementation and merge ownership

Branch `d19-sweep-refill`, head `8ab8746`. The refill change belongs to `ds41_prefill_seed`. The default `DS4_ROCM_STREAM_SEED_POLICY=always` refills at sweep end. With `cold`, only layers below half their share receive a refill. This keeps resident experts that the previous reply loaded. D17's sweep load functions are separate.

S3-FIFO is a second switch, `DS4_ROCM_STREAM_EVICT_POLICY=s3fifo`, default `lru`. Commits `d79081f` and `87da5f1` implement and build it. Ownership covers resident allocation, eviction, release, selected and batched lookups, and prefill-seed hit accounting in the ROCm runtime. Keep the D13 physical-removal path and its ordering when merging D22. A first admission enters a small FIFO, unless a ghost entry identifies a returning expert. Hits can promote an expert to the main FIFO and let it survive further passes. Protected experts rotate while their consumer is active.

## Offline replay of recorded S3-FIFO runs

CPU replay against the branch's original `scripts/d12/sim.py` found the first wrong victim on plain code after 49,391 correct lookups and 2,217 correct victims. At position 205 the runtime evicted layer 22, expert 45 while the simulator selected layer 3, expert 270. DSpark JSON first differed after 42,830 lookups and 3,109 victims. The sequence first differed after 39,936 lookups and 3,330 victims.

In `S3FIFO._evict_s`, the simulator promoted a hit small-queue expert and immediately evicted from the main queue if it exceeded its nominal share. The runtime promotes it and continues searching for a victim. Removing that eager eviction in a scratch copy fixes the observed divergence. The D19 simulator patch also mirrors the runtime’s bounded small-queue pass, bounded main-queue rotations and final fallback to small. This resolves a second difference on protected sets. Three CPU regression cases cover promotion, a fully protected main queue with a legal small-queue victim, and a fully protected cache. The Python interface raises a clean exception when no victim is available. These changes target the D19 branch. Earlier D12 policy results refer to the historical simulator revision. The independent driver used each call's protected IDs, the traced initial cache budget, sweep marks, and final lookup boundary. It modelled D13 lending and reclaim with a LIFO free list, reverse iteration of the resident array and swap-removal. It compared each predicted hit/miss and each ordered victim to the logged event. These counts include seed lookups.

## Queue 4 and integration decision

Queue 4 is `scripts/d19/q4.sh` on the D19 checkout. It checks the pause flag between jobs, the 12,288 MiB floor and NVMe telemetry, run exits, and reference digests or DSpark counts. It runs short prompt pairs and three 32k sessions. Use `--from TAG` within the allocated user systemd unit to enter an independent stage. Existing run tags and trace outputs are protected.

The long comparison begins at `--from d19-q4long-lru-a`. The four new tags have suffixes `lru-a`, `s3fifo-a`, `s3fifo-b`, and `lru-b`, in that order. Both arms use cold refill, the same D19 binary, 4,500 dynamic expert slots, a 163,840-token context and separate initially empty 32 GiB disk-KV namespaces. The A legs request 66k. Each B leg restores its own A transcript and checkpoint and requests 106k. At least one completed warm B turn must start at 100,000 tokens or more. The historical nominal-100k trace ended at 98,816.

Use `scripts/d19/session_qc.py SESSIONS_JSONL RUNS_DIR LEFT_TAG RIGHT_TAG` for matched timing and reply checks. `--overlap` permits a memory-guard stop and labels the compared subset. It reports how many reply token IDs were present in D8 for DSpark. The long driver separately reports restore TTFT and matched warm 100k-plus turns. Cold refill is a default-on candidate. The S3-FIFO default decision awaits measured matched sessions.
